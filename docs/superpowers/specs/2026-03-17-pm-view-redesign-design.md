# PM View Redesign (Internal) — Design Spec

**Date:** 2026-03-17
**Scope:** Внутренний PM‑вид для версии проекта
**File:** app/(dashboard)/projects/[id]/versions/[versionId]/page.tsx

## Summary
Обновить визуальный стиль внутреннего PM‑экрана под «стеклянный» тёмный интерфейс (как в референсе `portal-pm-internal.html`) без изменения логики Kinescope, аннотаций, роутинга и API. Добавить фильтры правок с реальной клиентской фильтрацией и ввести новый статус `VIEWED` в схеме БД. Поле «Ответить клиенту» доступно для OWNER и PM, монтажёр видит read‑only.

## Goals
- Перевести экран в новый glass‑style (фон, острова, акценты, типографика).
- Реализовать фильтры правок на клиенте (показывать/скрывать карточки).
- Добавить статус `VIEWED` в Prisma enum и использовать его в UI/счётчиках.
- Убрать кнопки статусов с карточек, заменить на один статичный бейдж.

## Non‑Goals
- Изменение логики Kinescope плеера.
- Изменение аннотаций и canvas‑слоя.
- Изменение роутинга/авторизации.
- Изменение API эндпоинтов и структуры БД, кроме добавления `VIEWED`.

- **Layout:** больше воздуха между блоками, без жёстких рамок/плоских фонов.

## Screen Structure
1. **Header (top bar)**
   - Плавающий glass‑остров, не на всю ширину (внутренние отступы и внешний воздух).
   - Сохраняет текущий контент (название, версия, кнопки), но визуально в glass‑style.
2. **Version tabs**
   - Горизонтальные pill‑табы.
   - Активная версия: `background: rgba(99,102,241,0.15)`, `border-color: rgba(99,102,241,0.35)`, `color: #a5b4fc`.
   - Таб создания версии — более лёгкий/пунктирный стиль.
3. **Video panel**
   - Контейнер плеера — glass‑card с мягкой рамкой.
   - Логика и компонент Kinescope не изменяются.
4. **Right panel (feedback)**
   - Панель правок — glass‑остров.
   - Карточки правок — стеклянные карточки с `border-radius: 13px`.

  - Pills: Все / Новые / Просмотрено / В работе / Готово.
  - Работают на клиенте (скрывают/показывают карточки).

## Feedback Cards & Threads
- **Статус:**
  - Удалить 3 кнопки статуса.
  - Оставить один **некликабельный** status‑badge.
- **Threads:**
  - Карточка раскрывается по клику.
  - Внутри — список ответов (как есть) и поле «Ответить клиенту».
- **Reply input access:**
  - **OWNER/PM:** активный input + кнопка отправки.
  - **EDITOR:** read‑only состояние (disabled) с тем же стилем.
  - Роли UI: использовать реальные enum значения `OWNER`, `PM`, `EDITOR`.

## Status Mapping & Filtering
- Добавить `VIEWED` в enum `FeedbackStatus`.
- Маппинг UI:
  - Новые → `NEW`
  - Просмотрено → `VIEWED`
  - В работе → `IN_PROGRESS`
  - Готово → `RESOLVED`
- `REJECTED` остаётся в схеме, но **не отображается в UI** и не участвует в фильтрах/счётчиках.
- Фильтры работают на клиенте по `feedbackResponse.status`.
- Логика авто‑просмотра: при первом рендере списка на экране версии все `NEW` автоматически переводятся в `VIEWED`
  через существующий PATCH `/api/feedback/:id` (новые эндпоинты не добавляем).
- Счётчики и список отражают **пост‑обновлённое** состояние: после первого рендера `NEW` становится 0, `VIEWED` растёт.
- По умолчанию активен фильтр **«Все»**.
- `REJECTED` исключается из списков, фильтров и счётчиков (полностью не показывается в UI).

## Implementation Notes (clarifications)
- **Auto‑view timing:** запускать один раз при первичной загрузке списка для выбранной версии (и повторять при смене версии).
- **Mutation strategy:** PATCH для каждого `NEW` элемента (батч‑эндпоинта нет). Допускается параллельный запуск запросов через `Promise.allSettled`.
- **Optimistic UI:** сразу помечать элементы как `VIEWED` в локальном состоянии; при ошибке PATCH — вернуть статус в `NEW` и показать toast об ошибке.
- **Toast system:** использовать существующий `toast` из `@/components/ui/toast` на этом экране.
- **Missing status:** если `feedbackResponse.status` отсутствует, трактовать как `NEW` (для фильтров и счётчиков).
- **REJECTED:** исключать из `visibleFeedback` до применения фильтра и подсчёта счётчиков.
- **Component boundaries:** остаёмся в одном файле `page.tsx`, допускаются локальные helper‑функции без выноса в общий UI‑слой.

- Если список правок пуст — показывать текущий empty‑state.
